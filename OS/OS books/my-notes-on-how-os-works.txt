return value => return to execute the main program (the program who call this function) with this value
so, every function, must have a return instruction, to return to the function who call this one, and continue running it

the OS has control over the CPU:
1. cooperatively: via system call
2. forcefully: via time interrupt

the OS decide via scheduler (part of OS) to 
- continue running the currently-running process
- switch to a different process via context switch (code)

context switch: save the context (register values) via assembly code
register the values of the currently-executed process onto the kernel stack 
and then when the OS resume its execution, he restore theses value from the kernel stack

communication between processes:
- Unix Pipes
- Sockets

workload : processes running on the system
process : sometime called job
polices : disciplines

scheduling disciplines:
-----------------------
1. FIFO = FCFS
- FIRST IN FIRST OUT
- FIRST COME FIRST SERVED

2. SJF: SHORTEST JOB FIRST
- runs the shortest job first, then the next shortest, ...
- runs each job to completion before running another
- ex: ten-items-or-less 

3. STCF : SHORT TIME-TO-COMPLETION FIRST
- any new job enter the system, the scheduler determines between the remaining jobs and the new job, witch has the least time left, and schedules it.

4. RR : Round robin scheduling
- while there are remaining jobs not finished in the run queue
	- RR run a job for a time slice (scheduling quantum) 
	- the switch to the next job in the run queue
- RR called time slicing
- the length of the time slice must be a multiple of the timer-interrupt period
- the shorter time slice is, the better the performance of RR under the response time metric.
	- time slice too short => the cost of switching (saving and restoring a few registers) will dominate the overall performance.
		- making it so long => minimize the cost of switching
		- making it so short => the system is no longer responsive
scheduler:
- stop one running job (process) temporarily and resuming (or starting) another
- can perform context switching
- types:
	* type 1: SJF and STCF:
		runs the shortest job remaining 
		optimizes turnaround time (délai d'exécution), but bad for response time 
	* type 2: 
		alternate between all jobs
		RR, optimizes response time, but bad for turnaround time
mechanisms used by the scheduler:
- time interrupts
- context switching

performance metrics:
- turnaround time: 
	- is the time at witch the job completes minus the time at witch the job arrived in the system
	- turnaround_time = time_completion - time_arrival
- response time: (interactivity)
	- is the time from when the job arrives and the first time it is scheduled.
	- time_response = time_first_run - time_arrival
