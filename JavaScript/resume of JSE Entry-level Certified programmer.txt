HTML
----
HyperText Markup Language, or HTML for short, 
is a set of tags used to describe the structure of a website. 
a language to describe the structure of a we page 
It allows us to give a page the format of a document containing sections, headers, paragraphs, lists, and the like.
Tag types are predefined. 
For example, the tag that specifies a paragraph is <p> and the tag for the first degree (largest) header is <h1>. 
The tag name must be placed in angle brackets. 
Tags are usually used in pairs, limiting a certain area of the document (we have an opening and a closing tag). 
The closing tag is different from the opening tag, because a slash appears before the name.
example: <p>It's just an ordinary paragraph.</p>
Often, tags can (and sometimes must) be placed within the range of other tags.
example: 
<body>
<p>It's just an ordinary paragraph.</p>
</body>

Minimal HTML document
---------------------
<!DOCTYPE html>
<html>
     <head>
     <title>Empty Page</title>
     </head>
     <body>
     </body>
</html>

- the declaration <!DOCTYPE html>. This is not a typical tag, as it is used to inform the browser that the whole document has been prepared according to HTML5. 
- <html> tag, which together with the </html> tag sets the boundaries of the document.
- <head>, contains additional information about the document, which must also be placed in tags. The most basic one is the <title> tag, which sets the title of the page mostly visible in the browser title bar.
- <body> element : the visible content of the web page should be placed there (e.g. our paragraph).

script tag
----------
The JavaScript code to be executed by the browser on the page must be attached to the HTML using the <script> tag, 
When loading the page, the code placed inside the <script> tags should be executed 
and there are two ways it can be done. 
1. The code can be embedded directly inside of the <script> and </script> tags, but this is only recommended when the code is short. 
2. Another approach is to use the "src" attribute to point to a separate file that contains the JavaScript code. 
This is especially true when the same code is going to be used on several pages, because repeating exactly the same code many times is bad practice, as any changes need to be applied to all the files; and additionally, it artificially increases the page size. 
The JavaScript file extension is .js.

HTML is read by the browser line by line, and script tags are executed right at the moment when the browser parses the <script> tag
<script> tags are inserted in the page header between the <head> and </head> tags, and we can insert many of them in a file, for example, in order to include JavaScript code from different files. This behavior can be changed for external scripts pointed to by the "src" attribute by using the "defer" or "async" attributes.

defer – means that the script should be executed after the whole page is loaded;
async – means that the script will be executed immediately, but in parallel to parsing the rest of the page.

example:
<script src="main.js"></script> : there is a reference to main.js (so this file will automatically be loaded, too).

hoisting
========
The JavaScript interpreter scans the program before running it, looking for errors in its syntax, among other things,
It searches for all variable declarations and moves them to the beginning of the range in which they were declared (to the beginning of the program if they are global, to the beginning of the block if it is a local let declaration, or to the beginning of the function if it is a local var declaration). 

principle of hoisting
---------------------
the declaration has been moved by the interpreter to the beginning of the range 
Hoisting only concerns the declaration, not initialization.

comments
========
- is plain text, totally ignored by the JavaScript interpreter, 
- usually serve to explain a certain piece of code,
- let you to imporve your work with the code by making it more readable
- help developers to express their intent for a given piece of code
- two types of comments: single-line and mutli-line comments 

make comment easy to read
-------------------------
- some comments make the code more harder to read
- Use comments when the code alone is not clear.
- Explain why, not just what the code does.
- Add comments when the code behaves unexpectedly or differently than expected to show that it is intentional.
- Remember that other developers may need to read and maintain your code.
- Even your own code can be difficult to understand months later.
- Clear comments improve readability, maintenance, and collaboration.
- Avoid unnecessary comments when the code is already self-explanatory.

single-line comment
-------------------
- Any code placed to the right of the double slash will be ignored by the interpreter. 
- example: // this is a single line comment
- tips: comment/uncomment using code editors (sublime text, vscode, ...) short cuts : ctrl + / : will comment/uncomment selected lines

multi-line comments
-------------------
- known as block comments
- is a comment that span multiple lines
- also allow to place a comment inside a linee
- created with: salsh and asterisk /* at the start and at the end of the comment
- example 1
/*
this is a block comment
and it can 
span multiple lines
*/
- example 2
let x /* because no better name*/ x = 10;
console.log(x);

use comments for documentation
-------------------------------
- Comments can be used to document code and explain how it works.
- Document functions, including:
What the function does
Required parameters
Returned values
- Files may include headers with information such as:
Author
License
Change history
- Tools like JSDoc can automatically generate documentation from specially formatted comments.
Properly written JSDoc comments can generate a website with detailed project documentation.
This documentation can include function descriptions, parameters, return values, and more.

comments used for Code Toggle
-----------------------------
Commenting out code lets you temporarily disable code without deleting it.
It is useful when:
You think a piece of code is causing a problem.
You want to test different options quickly.
You want to isolate the source of an issue.
Use single-line comments (//) to disable individual lines.
Use block comments (/* ... */) to disable larger sections or entire functions.
This technique is especially helpful for debugging and troubleshooting code.
