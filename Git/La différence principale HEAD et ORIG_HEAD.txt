La différence principale est que HEAD pointe vers votre position actuelle dans le dépôt (le commit ou la branche active), tandis que ORIG_HEAD sauvegarde l'ancienne position de HEAD juste avant une manipulation majeure ou risquée.HEAD (La position actuelle)C'est le pointeur permanent qui indique où vous en êtes.Il pointe généralement vers le nom de la branche active (ex: main) ou directement sur un commit si vous êtes en état de detached HEAD.Il se déplace à chaque fois que vous changez de branche (git checkout / git switch) ou que vous créez un nouveau commit.ORIG_HEAD (L'historique de secours)C'est une référence temporaire créée automatiquement par certaines commandes qui déplacent brutalement HEAD.Des commandes comme git reset, git merge, git rebase ou git am enregistrent l'état de HEAD dans ORIG_HEAD juste avant d'agir.Elle sert de raccourci pour annuler une grosse manipulation. Par exemple, si un git reset --hard supprime des choses par erreur, vous pouvez revenir en arrière instantanément avec git reset --hard ORIG_HEAD.Si vous le souhaitez, je peux vous montrer des exemples concrets d'utilisation de ORIG_HEAD pour rattraper une fusion (merge) ratée ou un déplacement de commit.
